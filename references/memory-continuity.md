# 学习记忆管理

## 定位与绑定

持续项目维护 `config/memory_binding.json`，记录项目标识、主题、数据库绝对路径、实际适配器与 schema 版本。角色通过同一个绑定读取当前课程。

首次建项创建记忆源并保存绑定；继续学习时先读绑定、共享规则和状态，再恢复未完成任务。路径移动时验证并统一更新绑定。多个课程无法区分时询问目标课程。

数据库与原始证据是学习事实来源；Markdown 状态、JSON 快照和报告是可重建视图。工程交接记录实现信息，学习进度由学习库管理。

绑定字段示例，生成时填入实际值：

```json
{
  "binding_version": 1,
  "project_id": "course-uuid",
  "subject_id": "subject-identifier",
  "database_path": "/absolute/path/to/learning.sqlite3",
  "adapter": "actual-project-adapter",
  "schema_version": 1,
  "verified_at": "actual-ISO-8601-timestamp"
}
```

## 四层存储

- 稳定记忆：目标、偏好、能力事实与候选，带适用范围、证据、时间和事实状态。
- 情景记忆：活动、题目或任务、原答或作品引用、量规、反馈、提示和时间。
- 知识记忆：概念、技能、错误模式、资源、熟练度、到期时间与复习历史。
- 运行记忆：路线、计划、暂停点、当前任务、角色队列和交接状态。

优先用 SQLite 保存结构化记录与全文检索。大文件如音频、图片和作品保存在项目数据目录，数据库记录路径、来源和关联事件。

## 跨课程与跨对话

每条课程记录带 project_id；概念与技能再带 subject_id、skill_id。业务唯一约束、检索、统计和队列领取按项目隔离。

可以一库多课，也可以每课独立数据库。按实际规模选稳定方案，并在项目配置写清楚。共享学习偏好带来源与适用范围；特定主题的能力证据保留在相应课程。

新 Chat 或角色启动读取绑定与有界上下文；更多细节按事件 ID 检索。跨角色通过持久队列交接，不依赖私有对话历史。

## 记录和修正

- occurred_at 是已知发生时间，recorded_at 是实际录入时间；未知发生时间保持 null。
- 用户原答和作品引用保留，规范化、量规判断与反馈另存。
- 提示、用时和独立程度未知时标记未知。
- 同一事件键同载荷可以安全重试；同键不同载荷进入修正流程。
- 修正保留前后值、原因、操作者与时间，重算相关统计、复习及引用结论。
- 候选能力判断需要多次相关证据后再确认为稳定状态。

## 启动与恢复

角色启动入口返回：角色规则、当前目标、相关核心信息、计划、暂停点、近期活动、到期复习和待办。启动入口的名称由实际项目实现决定。

需要检查数据库结构时，可使用：

```bash
python3 /path/to/good-good-study/scripts/probe_memory.py \
  --db '/absolute/path/to/learning.sqlite3'
```

该脚本只读结构、版本、行数和完整性，不加载学习答案或角色上下文，不初始化和迁移数据库。

## 备份与迁移

SQLite 使用一致性 backup API；运行中的 WAL 数据库需要完整处理。迁移有版本、先备份并验证兼容性。恢复覆盖前检查当前授权、保留安全副本并协调停写。

完整归档包括实际存在的媒体、作品和私有配置。数据库、原始输入、媒体、导出和私人学习报告默认不提交远程仓库。

验证关闭当前进程后，新进程仍能读到最新活动、暂停点、复习安排和未完成交接。
