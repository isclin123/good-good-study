# 角色与对话协作

## 按学习目标分工

总控负责路线与计划，专项教练负责各自模块，测评负责证据与复盘，需要资料核实时再设置研究角色。角色数量随课程规模调整，可合并职责。

示例：

- 数学与统计：概念、推理与证明、计算与数据实践。
- 编程与工具：基础、设计与调试、项目实践。
- 语言与沟通：理解、表达、情境应用。
- 科学与研究方法：基础概念、方法分析、实验或复现。
- 音乐与艺术：基础感知、技术训练、作品实践与反馈。
- 生活与职业技能：原理、操作练习、真实场景任务。

专项更新本领域记录，向总控交接计划建议；总控汇总后维护总计划。用户可指定或调整分工。

## 创建实际 Chat

持续项目采用分工对话。按宿主当前授权和工具规则操作：

1. 发现项目、对话列表、创建和状态查询工具，读取实际定义。
2. 定位课程项目及已有角色对话，优先复用可继续的 Chat。
3. 先准备共享目录、记忆绑定、角色提示和实际启动入口。
4. 初始提示包含项目根目录、项目标识、角色、先读规则、上下文入口及当前等待状态。
5. 默认使用同一项目本地环境和记忆绑定，保留用户默认模型。
6. 异步创建后确认实际状态，登记 thread ID、host、角色和状态到 config/chats.json。
7. 专项对话加载上下文后等待用户进入该角色；当前教学从总控协调的任务开始。
8. 向用户提供实际创建的链接或入口；工具缺少项目注册或创建能力时给出准确的手动步骤和角色启动文件。

应用中的长期 Chat 和当前任务的临时 subagent 按各自用途使用。后续向其他 Chat 发送消息按当前授权处理；本地队列用于持久交接。

## 角色启动模板

生成时填入实际值和可运行命令：

```text
你在学习项目 {project_id} 中担任 {role}。
根目录：{absolute_project_root}。
先读 AGENTS.md、config/memory_binding.json 和 agents/{role}.md。
执行角色上下文入口：{verified_start_command}。
读取目标、计划、暂停点、待办和近期相关证据。
职责：{responsibilities}。协作边界：{boundaries}。
记录与交接入口：{verified_record_and_handoff_commands}。
保存真实输入，未知信息保持未知；冲突附证据提交复盘。
总计划由总控维护。
当前加载上下文并等待用户；收到学习请求后接续当前任务。
```

启动文件按角色放入 agents/，可提供便于用户复制的简短启动语。

## 持久交接协议

任务包含 task_id、project_id、dedupe_key、sender、recipient、kind、source_ids、payload、status、created_at 和 available_at。

payload 说明具体发现和请求，source_ids 引用实际活动或测评。任务状态可为 pending、claimed、completed、retry、failed。领取和完成在事务中验证租约与归属；稳定去重键保护重试和重复消费。

专项记录学习结果 → 测评汇总证据与建议 → 总控重读最新证据并更新计划 → 相关专项读取下一任务。

来源修正后重新评估依赖的交接与计划。队列入库、角色读取和任务处理完成分别记录。

## 恢复验证

在临时库中以独立进程模拟：专项保存练习 → 测评读取并建议 → 总控读取并调整 → 专项看到新任务。各进程仅共享数据库和项目文件。

同时验证事件重试不重复计数、未完成队列重启后存在。应用 Chat 间的端到端验证另按实际创建和运行结果报告。
